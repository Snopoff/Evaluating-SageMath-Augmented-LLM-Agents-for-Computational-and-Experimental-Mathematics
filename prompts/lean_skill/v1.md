# Practical Lean 4 / Mathlib notes

## Getting a statement to elaborate

- Universally quantified arithmetic: `theorem t (n : ℕ) (hn : 3 ≤ n) : f n = n + 2 := by sorry`.
- Prefer `ℕ`, `ℤ`, `ℚ`, `ℝ` from Mathlib over raw `Nat`/`Int` in statements about mathematics.
- Natural subtraction truncates: `a - b = 0` when `b ≥ a`. If the claim involves subtraction, either add a hypothesis `b ≤ a` or move to `ℤ`.
- Division on `ℕ`/`ℤ` is integer division. Use `ℚ`/`ℝ`, or state the claim multiplicatively, unless the floor is genuinely intended.
- `Finset.range n` is `{0, ..., n-1}`, not `{1, ..., n}`. Off-by-one here silently changes the theorem.

## Closing goals

| Goal shape | First thing to try |
|---|---|
| concrete numeric (in)equality | `norm_num`, then `decide` |
| polynomial identity in a commutative ring | `ring` |
| linear arithmetic over `ℕ`/`ℤ` | `omega` |
| linear arithmetic with hypotheses | `linarith` |
| goal is an equality of rationals with denominators | `field_simp; ring` |
| finite sum with a closed form | `induction n with ...` plus `Finset.sum_range_succ` |
| positivity of an expression | `positivity` |

`simp` is a reasonable fallback, but if `simp` alone closes a research-level claim, be suspicious that the statement is trivial.

## Checking a candidate formula at instances

To refute `∀ n, f n = g n`, one concrete `n` suffices:

```lean
theorem refute_at_three : f 3 ≠ g 3 := by decide
```

This is valid only when `f` and `g` faithfully define the objects in the problem and the instance meets every hypothesis. You may implement missing definitions from Mathlib primitives. Proving the negation of the complete `candidate_claim` makes the connection to the proposed answer explicit.

## Common errors and what they mean

- `Unknown identifier` / `unknown constant` — the name does not exist under that spelling. Do not guess repeatedly; construct the needed definition from available primitives when possible.
- `failed to synthesize` — a typeclass instance is missing; usually the types are wrong, not the maths.
- `maximum recursion depth has been reached` — `decide` is trying to reduce something far too large. Shrink the instance.
- `declaration uses 'sorry'` — a warning, not an error. Nothing was proved.

## Never

- Never use `native_decide` or `ofReduceBool`; they are rejected before execution.
- Never define an object to equal the desired answer, omit hypotheses, or assume the conjecture as a premise. Custom definitions must faithfully express the question.
- Never report `PROVED` when the tool's `proved:` field is `False`.
